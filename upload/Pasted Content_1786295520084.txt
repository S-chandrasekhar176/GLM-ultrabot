## 1.1 Project Name

**UltraBot Web** — Algorithmic Trading Terminal for NSE

## 1.2 One-Line Description

A semi-automated, web-based algorithmic trading system for Indian NSE markets that scans stocks using news + technical analysis, identifies high-probability opportunities through adaptive strategies + AI scoring, presents them to the user with full probability analysis for confirmation, and executes with dynamic position sizing, partial profit booking, and multi-layer risk management.

## 1.3 Core Philosophy

```
1. News tells WHERE to look     (watchlist builder)
2. Strategies tell WHEN to trade (signal generator)
3. Risk engine tells WHETHER to trade (safety net)
4. User gives FINAL YES/NO      (human in the loop)
5. System executes HOW MUCH     (dynamic sizing)
6. System manages EXIT          (partial booking + trailing SL)
```

## 1.4 Target User

Single user (you). Private. Personal trading terminal. Not a public product.

## 1.5 Target Market

Indian National Stock Exchange (NSE) — Equity Segment + Options Segment (NFO)

## 2.2 Data Flow — Complete Pipeline

```
PRE-MARKET (8:00 - 9:15 AM)
━━━━━━━━━━━━━━━━━━━━━━━━━━━
  1. News Engine fetches overnight news
     → NSE corporate actions
     → Result calendar for today
     → Moneycontrol/ET RSS feeds
     → Bulk/block deals from yesterday
  
  2. News Engine builds Morning Watchlist
     → Stocks with news catalyst
     → Stocks with results today
     → Stocks with corporate actions
  
  3. Technical Pre-Scan on F&O universe (185 stocks)
     → Gap detection (pre-market prices)
     → Previous day breakouts near completion
     → Stocks with unusual volume yesterday
  
  4. Merge → Morning Watchlist (20-40 stocks)
  
  5. Telegram: Morning briefing sent
     "Today's watchlist: RELIANCE, INFY, TCS..."
     "Key events: INFY Q3 results, HDFCBANK ex-dividend"


MARKET OPEN (9:15 AM)
━━━━━━━━━━━━━━━━━━━━━━
  6. WebSocket connects to broker (Angel One / Shoonya)
     → Live prices stream for watchlist stocks
     → Candle data (1min, 5min, 15min) building
  
  7. Market Regime Detector runs
     → Analyzes Nifty trend, VIX, sector movement
     → Classifies: Bull / Bear / Sideways / Volatile
     → Activates appropriate strategies
     → Deactivates inappropriate strategies
  
  8. SCANNING LOOP (every 1-5 minutes)
     │
     ├── Kronos Scanner
     │   → Scans watchlist stocks
     │   → Ranks by opportunity score
     │   → Updates hot list ranking
     │
     ├── Strategy Engine
     │   → Each active strategy checks each watchlist stock
     │   → Generates signals (entry, SL, target, direction)
     │   → Kronos scores each signal (confidence 0-1)
     │
     ├── Risk Engine (13 Gates)
     │   → G1:  Max open positions
     │   → G2:  Max sector concentration
     │   → G3:  Max position size
     │   → G4:  Max daily trades
     │   → G5:  Max daily loss
     │   → G6:  Correlation check
     │   → G7:  VIX filter
     │   → G8:  Time-of-day filter
     │   → G9:  Price mismatch guard
     │   → G10: Min signal confidence
     │   → G11: Max drawdown
     │   → G12: Margin check
     │   → G13: Duplicate signal check
     │
     ├── Dynamic Position Sizer
     │   → Kelly base fraction
     │   → Adjust for signal confidence
     │   → Adjust for VIX/volatility
     │   → Adjust for current drawdown
     │   → Adjust for available capital
     │   → Check minimum position size
     │   → Final quantity determined
     │
     └── If signal passes all gates + sizing OK:
         → OPPORTUNITY PRESENTED TO USER
  
  9. OPPORTUNITY PRESENTED (WebSocket push to browser)
     │
     ├── Browser shows confirmation dialog:
     │   • Stock name, direction (BUY/SELL)
     │   • Strategy name + historical win rate
     │   • Entry, SL, Target, R:R ratio
     │   • Kronos confidence score
     │   • Position size + capital required
     │   • Equity trade details + Options trade details
     │   • All 13 risk gate results
     │   • Market context (VIX, Nifty trend, sector)
     │   • Backtest stats for this strategy+stock combo
     │
     ├── User clicks CONFIRM → order placed
     │   ├── Paper mode: simulated in memory + DB
     │   └── Live mode: sent to broker API
     │
     ├── User clicks SKIP → logged as skipped
     │
     └── User clicks REMIND → re-alert after X minutes
  
  10. POSITION MANAGEMENT (continuous while position open)
      │
      ├── Price hits Level 1 (1:1 R:R)
      │   → Book 50% quantity
      │   → Move SL to entry (risk-free)
      │   → Telegram: partial booking alert
      │
      ├── Price hits Level 2 (1.5:1 R:R)
      │   → Book 25% quantity
      │   → Trail SL
      │
      ├── Price hits Target (2:1 R:R)
      │   → Exit remaining or trail
      │
      ├── Price hits SL
      │   → Exit full quantity
      │   → Record loss
      │   → Check daily loss limit
      │
      └── Trailing SL keeps moving
          → If price reverses, SL triggers exit
  
  11. DAILY RISK MONITORING
      │
      ├── Track daily P&L continuously
      ├── At 67% of max daily loss → reduce new position size 50%
      ├── At 100% of max daily loss → STOP new trades for day
      ├── At 5 consecutive losses → cool-off 30 minutes
      ├── At max daily trades → no new trades
      └── All limits configurable by user


POST-MARKET (3:30 - 4:00 PM)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  12. Square off all intraday positions
  13. Calculate final P&L with fees
  14. Save session state to SQLite
  15. Generate EOD report
  16. Send EOD via Telegram
  17. Prepare next-day hints
```

## 3.2 Database Schema (SQLite)

```
TABLE: sessions
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  id              TEXT PRIMARY KEY     (UUID)
  start_time      DATETIME
  end_time        DATETIME
  mode            TEXT                 (paper / live)
  broker          TEXT                 (angel_one / shoonya)
  initial_capital REAL
  final_capital   REAL
  status          TEXT                 (active / closed / crashed)
```

## 3.4 Risk Gates — Detailed Specification

```
GATE 1: MAX OPEN POSITIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━
  Check:    current_open_positions >= max_positions
  Default:  max_positions = 5
  Action:   REJECT if limit reached
  Config:   User can change max_positions


GATE 2: SECTOR CONCENTRATION
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Check:    How many positions already in same sector as new signal
  Default:  max_per_sector = 2
  Action:   REJECT if sector limit reached
  Why:      Don't put all money in banking if you already have 2 bank stocks
  Sectors:  Banking, IT, Energy, Pharma, Auto, FMCG, Infra, Metal, etc.


GATE 3: MAX POSITION SIZE
━━━━━━━━━━━━━━━━━━━━━━━━━━
  Check:    position_value > max_position_pct × total_capital
  Default:  max_position_pct = 25%
  Action:   REJECT if exceeds (or resize if possible)
  Also:     Check available capital (balance aware)


GATE 4: MAX DAILY TRADES
━━━━━━━━━━━━━━━━━━━━━━━━━━
  Check:    trades_today >= max_daily_trades
  Default:  max_daily_trades = 10
  Action:   REJECT new signals for rest of day


GATE 5: MAX DAILY LOSS
━━━━━━━━━━━━━━━━━━━━━━━━━━
  Check:    daily_pnl <= -max_daily_loss
  Default:  max_daily_loss = 3% of capital
  Action:   REJECT new trades + tighten existing SLs
  Warning:  At 67% usage → reduce new position sizes by 50%


GATE 6: CORRELATION CHECK
━━━━━━━━━━━━━━━━━━━━━━━━━━
  Check:    Is new signal highly correlated with existing positions?
  Default:  max_correlated = 2
  Action:   REJECT if too many correlated positions
  Example:  Already have SBI + HDFCBANK → reject PNB (all banking)


GATE 7: VIX FILTER
━━━━━━━━━━━━━━━━━━
  Check:    current_vix > vix_threshold
  Default:  vix_threshold = 20
  Action:   REJECT new trades when VIX too high
  Why:      High VIX = high volatility = unpredictable = dangerous


GATE 8: TIME OF DAY
━━━━━━━━━━━━━━━━━━━━━
  Check:    Current time outside preferred trading window
  Default:  New trades: 9:30 AM - 2:30 PM only
  Action:   REJECT new trades outside window
  Why:      First 15 min = ORB formation. Last hour = squaring off.
  Note:     Can configure different windows per strategy


GATE 9: PRICE MISMATCH GUARD
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Check:    |signal_entry_price - broker_live_ltp| / broker_live_ltp > threshold
  Default:  threshold = 0.5%
  Action:   REJECT + refresh feed + alert
  Why:      Prevents trading on stale/hallucinated prices
  Critical: This is the P0 bug guard


GATE 10: MINIMUM SIGNAL CONFIDENCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Check:    kronos_score < min_confidence
  Default:  min_confidence = 0.6
  Action:   REJECT low-confidence signals
  Why:      Don't trade weak signals. Wait for strong ones.


GATE 11: MAX DRAWDOWN
━━━━━━━━━━━━━━━━━━━━━━━
  Check:    current_drawdown > max_drawdown_pct
  Default:  max_drawdown_pct = 5% (per day)
  Action:   PAUSE engine + alert
  Different: From G5 (daily loss). This tracks peak-to-trough.


GATE 12: MARGIN CHECK
━━━━━━━━━━━━━━━━━━━━━━━
  Check:    required_margin > available_margin
  Action:   REJECT or RESIZE to fit available margin
  Live mode: Check actual broker margin
  Paper mode: Check virtual capital


GATE 13: DUPLICATE SIGNAL
━━━━━━━━━━━━━━━━━━━━━━━━━━
  Check:    Same symbol + same direction signal in last X minutes?
  Default:  X = 15 minutes
  Action:   REJECT duplicate (keep first one)
  Why:      Multiple strategies may fire same signal. Take only first.
```

## 3.5 Dynamic Position Sizing — Detailed Logic

```
STEP 1: BASE KELLY FRACTION
━━━━━━━━━━━━━━━━━━━━━━━━━━━
  win_rate     = from strategy_performance table (historical)
  avg_win      = average winning trade pnl
  avg_loss     = average losing trade pnl
  kelly_f      = (win_rate × avg_win - (1 - win_rate) × avg_loss) / avg_win
  kelly_f      = clamp(kelly_f, 0.02, 0.25)  // Never below 2%, never above 25%
  
  base_size    = total_capital × kelly_f


STEP 2: CONFIDENCE ADJUSTMENT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  kronos_score = signal.confidence  (0 to 1)
  
  if kronos_score >= 0.8:   confidence_mult = 1.0    (strong signal)
  if kronos_score >= 0.6:   confidence_mult = 0.8    (decent signal)
  if kronos_score >= 0.4:   confidence_mult = 0.5    (weak signal)
  if kronos_score <  0.4:   REJECT by G10           (too weak)
  
  adjusted_size = base_size × confidence_mult


STEP 3: VOLATILITY ADJUSTMENT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  vix = current_vix
  
  if vix <= 14:   vol_mult = 1.0    (calm market, normal size)
  if vix <= 18:   vol_mult = 0.85   (slightly nervous)
  if vix <= 22:   vol_mult = 0.65   (worried, reduce)
  if vix >  22:   vol_mult = 0.4    (fearful, much smaller)
  
  adjusted_size = adjusted_size × vol_mult


STEP 4: DRAWDOWN ADJUSTMENT
━━━━━━━━━━━━━━━━━━━━━━━━━━━
  daily_pnl_pct = day_pnl / total_capital
  
  if daily_pnl_pct >= 0:      dd_mult = 1.0    (profitable day, normal)
  if daily_pnl_pct >= -1%:    dd_mult = 0.9    (small loss, slight reduce)
  if daily_pnl_pct >= -2%:    dd_mult = 0.7    (moderate loss, reduce)
  if daily_pnl_pct >= -3%:    dd_mult = 0.4    (approaching limit, heavy reduce)
  if daily_pnl_pct <  -3%:    STOP new trades  (limit hit)
  
  adjusted_size = adjusted_size × dd_mult


STEP 5: CAPITAL AVAILABILITY
━━━━━━━━━━━━━━━━━━━━━━━━━━━
  available = free_capital × 0.9   (never use 100%)
  
  if adjusted_size <= available:
      final_size = adjusted_size   (we can afford it)
  else:
      final_size = available       (cap at what we can afford)
  
  if final_size < min_position_size (e.g., ₹5,000):
      REJECT: "Position too small after adjustments"


STEP 6: CONVERT TO QUANTITY
━━━━━━━━━━━━━━━━━━━━━━━━━━━
  qty = floor(final_size / entry_price)
  
  if segment == "OPT":
      lot_size = option_lot_size[symbol]  (e.g., RELIANCE lot = 250)
      qty = floor(final_size / (premium × lot_size)) × lot_size
  
  final_capital_required = qty × entry_price  (or qty × premium × lot_size for options)
```

## 3.6 Partial Profit Booking — Detailed Logic

```
WHEN POSITION IS OPENED:
━━━━━━━━━━━━━━━━━━━━━━━━
  entry  = position.entry_price
  sl     = position.sl_price
  target = position.target_price
  qty    = position.total_quantity
  
  risk   = |entry - sl|                          (risk per share)
  
  level1_target = entry + (risk × 1.0)          (1:1 R:R)
  level2_target = entry + (risk × 1.5)          (1.5:1 R:R)
  level3_target = entry + (risk × 2.0)          (2:1 R:R) = original target
  
  (For SELL positions, subtract instead of add)


LEVEL 1 HIT: price reaches level1_target
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  book_qty    = ceil(qty × 0.50)                (book 50%)
  remaining   = qty - book_qty
  book_pnl    = book_qty × |level1_target - entry|
  
  Action:
    → Exit book_qty shares at level1_target
    → Move SL to entry price (risk-free now)
    → Record partial booking in position.booked_levels
    → Telegram: "Partial booking L1: {symbol} {book_qty} shares @ {level1_target}"
    → WebSocket: push updated position to browser


LEVEL 2 HIT: price reaches level2_target
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  book_qty    = ceil(remaining × 0.50)          (book 50% of remaining = 25% of original)
  remaining   = remaining - book_qty
  book_pnl    = book_qty × |level2_target - entry|
  
  Action:
    → Exit book_qty shares at level2_target
    → Trail SL to level1_target (locked L1 profit)
    → Record partial booking
    → Telegram: "Partial booking L2: {symbol} {book_qty} shares @ {level2_target}"


LEVEL 3 HIT: price reaches level3_target (original target)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Option A: Exit remaining shares at target
  Option B: Trail SL with Supertrend and let it run (if momentum is strong)
  
  Default: Option A (exit at target)
  Config:  User can choose Option B per strategy


TRAILING STOP LOSS
━━━━━━━━━━━━━━━━━━━
  After Level 1 booked (risk-free):
    → Trail SL method: Step trail or Supertrend trail
    
    Step Trail:
      → Every time price moves +1% from last SL, move SL up by 0.5%
      → SL never moves down
    
    Supertrend Trail:
      → Use Supertrend indicator as trailing SL
      → More adaptive, follows price action
```

```
  CRITICAL  → Engine cannot continue. Requires immediate attention.
              Example: Broker disconnected, DB corrupted, all feeds down

              Example: One feed down (backup active), token expiring soon
              Action: Auto-recover, Telegram info, UI yellow banner
              
  INFO      → Normal operational event. Logged only.
              Example: Token refreshed, scan completed, signal skipped
              Action: Log only, no alert


ERROR CATEGORIES + AUTO-RECOVERY:
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  BROKER ERRORS:
  ─────────────
  AG8001 (Token Expired):
    What:     Angel One session token expired
    Why:      Tokens expire every 24 hours
    Recovery: Auto-re-authenticate using stored credentials
    If fails: Alert user to manually reconnect
    Time:     Retry 3 times with 5-second gaps

  Broker Connection Lost:
    What:     Cannot reach broker API
    Why:      Internet issue or broker server down
    Recovery: Retry 5 times with exponential backoff (5s, 10s, 20s, 40s, 80s)
    If fails: Switch to backup broker (if configured)
    If both:  Pause engine, alert user

  Order Rejected:
    What:     Broker rejected an order
    Why:      Many reasons (insufficient margin, price band, circuit limit)
    Recovery: Cannot auto-recover. Log reason. Alert user.
    Action:   Mark signal as failed with reason

  FEED ERRORS:
  ────────────
  WebSocket Disconnected:
    What:     Live price feed dropped
    Why:      Network interruption, broker restart
    Recovery: Auto-reconnect 5 times with backoff
    If fails: Switch to backup feed
    If both:  Pause signal generation (existing positions still tracked)

  Stale Data Detected:
    What:     No new data received for 30+ seconds
    Why:      WebSocket silently disconnected
    Recovery: Disconnect and reconnect
    If fails: Switch feed

  Price Mismatch:
    What:     Signal price deviates >0.5% from broker LTP

    If still: Reject signal, alert user

  ────────────

    Action:   Stop new trades. Alert user. Tighten existing SLs.
```

## 3.11 Strategies — Detailed Specifications

```
CORE STRATEGIES (7):
━━━━━━━━━━━━━━━━━━━━

1. BREAKOUT
   ─────────
   Logic:      Price breaks above resistance or below support with volume
   Entry:      Close > Resistance + buffer (or Close < Support - buffer)
   SL:         Resistance level (or Support level)
   Target:     Entry + 2× risk (or next resistance level)
   Volume:     Must be 1.5× average volume on breakout candle
   Timeframe:  5min, 15min
   Best in:    Bull, Bear (shorts)
   Worst in:   Sideways (false breakouts)

2. MEAN REVERSION
   ───────────────
   Logic:      Price deviated far from mean, expected to snap back
   Entry:      Z-score of (price - SMA) > 2.0 (oversold) or < -2.0 (overbought)
   SL:         Entry ± 1.5× standard deviation
   Target:     SMA (mean)
   Timeframe:  5min, 15min
   Best in:    Sideways
   Worst in:   Strong trends (gets destroyed)

3. MOMENTUM
   ─────────
   Logic:      Strong directional move with increasing volume
   Entry:      Rate of change > threshold AND volume > 2× average
   SL:         Entry - 1× ATR
   Target:     Entry + 2× ATR
   Timeframe:  5min
   Best in:    Bull, Bear
   Worst in:   Choppy, sideways

4. OPENING RANGE BREAKOUT (ORB)
   ─────────────────────────────
   Logic:      Break of first 15-30 minute high/low
   Entry:      Price > Opening Range High (BUY) or < Opening Range Low (SELL)
   SL:         Opening Range midpoint or opposite end
   Target:     Entry + 2× risk
   Volume:     Breakout candle volume > OR average volume
   Timeframe:  5min (range built on 15min candles from 9:15-9:30)
   Best in:    All regimes (especially trending)
   Time gate:  Only between 9:30 - 11:00 AM

5. RSI DIVERGENCE
   ───────────────
   Logic:      Price makes new high but RSI doesn't (bearish divergence) or vice versa
   Entry:      On divergence + confirmation candle
   SL:         Recent swing high/low
   Target:     Entry - 2× risk (bearish) or Entry + 2× risk (bullish)
   RSI period: 14
   Timeframe:  15min
   Best in:    Reversals, Bear trend
   Worst in:   Strong bull trend

6. SUPERTREND
   ───────────
   Logic:      Follow Supertrend indicator direction changes
   Entry:      Supertrend flips from sell→buy (BUY) or buy→sell (SELL)
   SL:         Supertrend value (it acts as trailing SL)
   Target:     Entry + 2× ATR (or trail with Supertrend)
   Params:     Period=10, Multiplier=3
   Timeframe:  5min, 15min
   Best in:    Bull, Bear
   Worst in:   Sideways (whipsaws)

7. VWAP REVERSION
   ───────────────
   Logic:      Price deviated far from VWAP, expected to revert
   Entry:      Price > VWAP + 2× StdDev (overbought, SELL) or Price < VWAP - 2× StdDev (oversold, BUY)
   SL:         VWAP ± 3× StdDev
   Target:     VWAP
   Timeframe:  5min
   Best in:    Sideways, intraday
   Worst in:   Strong trends


ADVANCED STRATEGIES (7):
━━━━━━━━━━━━━━━━━━━━━━━━

8. GAP FILL
   ─────────
   Logic:      Gap up/down at open. Trade the gap fill (price returns to previous close)
   Entry:      If gap up > 0.5% AND first 5-min candle is red → SELL (gap fill)
               If gap down > 0.5% AND first 5-min candle is green → BUY (gap fill)
   SL:         Day's high/low
   Target:     Previous close (gap fill target)
   Timeframe:  1min, 5min
   Best in:    Gap days
   Time gate:  9:15 - 10:30 AM only

9. SECTOR ROTATION
   ────────────────
   Logic:      When a sector starts outperforming, trade the strongest stock in that sector
   Entry:      Sector momentum > threshold → buy strongest stock in sector
   SL:         Sector ETF/indicator level breakdown
   Target:     Entry + 2× risk
   Timeframe:  15min
   Best in:    Sector rotation days

10. MULTI-TIMEFRAME CONFLUENCE
    ───────────────────────────
   Logic:      Signal valid only when 2+ timeframes agree
   Entry:      5min trend = 15min trend = 1hr trend (all same direction)
   SL:         Based on 5min ATR
   Target:     Entry + 2× risk (15min based)
   Timeframe:  5min + 15min + 60min
   Best in:    All (reduces false signals in any regime)

11. ORB + VOLUME CONFIRMATION
    ──────────────────────────
   Logic:      ORB breakout but with strong volume confirmation (2×+ OR volume)
   Entry:      Same as ORB but volume must be 2×+ opening range average
   SL:         Same as ORB
   Target:     Same as ORB
   Best in:    Bull, Bear (filters false breakouts better than plain ORB)

12. TREND EXHAUSTION
    ────────────────
   Logic:      Trend running too long + momentum decreasing + divergence appearing
   Entry:      After 3+ Supertrend direction candles + decreasing RSI + volume declining
   SL:         Recent swing high/low
   Target:     Entry - 1.5× risk (counter-trend)
   Best in:    End of trends, reversals
   Risk:       Higher risk (counter-trend). Size reduced automatically.

13. NEWS MOMENTUM
    ──────────────
   Logic:      After news catalyst, wait for first pullback then enter in news direction
   Entry:      Stock in news → initial move → pullback to VWAP/EMA → entry in original direction
   SL:         Pullback low (or high for shorts)
   Target:     Entry + 2× risk
   Best in:    Post-news, trending
   Requires:   News Engine + technical confirmation

14. ADAPTIVE SUPERTREND
    ────────────────────
   Logic:      Supertrend that auto-adjusts multiplier based on VIX
   Params:     Base period=10, Multiplier = 3 + (VIX-15)/10
               Low VIX (12) → multiplier 2.5 (tighter, more signals)
               High VIX (25) → multiplier 3.5 (wider, fewer signals)
   Entry:      Same as Supertrend but with adaptive multiplier
   Best in:    All regimes (self-adapts)
```

## 6.3 Core Design Principles

```
1. News = WHERE to look, not WHEN to trade
2. Strategies = WHEN to trade (technical confirmation)
3. Market Regime = WHICH strategies to activate
4. Risk Engine = WHETHER to trade (safety)
5. User = FINAL YES/NO (human in the loop)
6. Dynamic Sizing = HOW MUCH to trade
7. Partial Booking = HOW to exit (lock profits, reduce risk)
8. Daily Limits = WHEN to stop (preserve capital)
9. Clear Errors = WHAT failed, WHY, HOW to fix
10. Fresh Build = No legacy, clean architecture
11. Paper First = Prove it works before real money
12. Private = Your money, your bot, your rules
```
